# Release 2026-09-21 — the 2026-08-07 pentest fixes

Four commits on `claude/loving-cannon-ba5tbt` (`473397e`, `57d390d`, `22318a1`,
`e052fa3`), merged `--no-ff` into `master`. This file is the review guide, the
deploy order and the on-device checks, in the order to do them.

## 1. Review — the five places worth a human's eyes

The diff is ~1900 lines and was pentested by a fresh agent (7 findings, all
fixed in `e052fa3`). These are the spots where a *decision* was made that you
may want differently, plus the two protocol changes:

1. **`backend/accounts.py` `auth_verify`** — login is now Ed25519 **and**
   ML-DSA-65, and an unknown user runs both verifications against a decoy.
   This is the change that makes an old APK unable to log in. Read it once;
   it is ~30 lines.
2. **`client/app.js`, the `pending` case (search `sessionRoomMine`)** — a
   creator whose invitee connected first is now *refused* with an
   explanation, not made a guest. The alternative (warn, continue as guest)
   would keep the old UX but leave the room with nobody approving anybody.
   If you want the soft version, it is a five-line change here.
3. **`client/chats.js` `unlock`, the `!tagged` branch** — every existing user
   sees one "Open anyway" prompt in the Chats view on first unlock after this
   release, because every deployed chat store is untagged. The silent variant
   was shown to reopen F-ATREST-005 with one `removeItem`; that is why the
   prompt is unconditional.
4. **`client/contacts.js` `unlock`, the `!raw` branch** — on Android,
   "Forget identity" then restoring the *same* identity backup on the same
   phone now prompts `DELETED_CONTACTS_ADOPTION` (the floor cannot be
   lowered, and the state is identical to an attacker's two deletions). A
   *new* identity is unaffected.
5. **`client/nativefloor.js`** — the floor capture moved out of `otp.js`
   verbatim and became a per-module call. Diff it against the old block in
   `otp.js` (`git show 80a002d:client/otp.js | sed -n 106,206p`): only the
   `export`s and the `what` parameter of `floorUnavailableError` are new.

Everything else is mechanical (limiter keying, no-strip rule, vouch TOCTOU,
revoked pins, tests).

## 2. Deploy — relay, web client and APK as ONE unit

Order matters: the relay refuses Ed25519-only logins, so an old APK cannot
log in and its mailbox poller hits a 401 every 6 s. Install the APK first,
then switch the relay.

```bash
# on the machine with the Android SDK, from the repo root, on master
git checkout master && git pull
(cd android && ./gradlew assembleRelease)          # or assembleDebug for the test phone
adb install -r android/app/build/outputs/apk/release/app-release.apk
# do NOT open the app yet — its bundled client expects the new relay

bash deploy/deploy-2026-09-21.sh                   # backup, rsync, restart, verify
```

Then on the phone: open the app, unlock, expect exactly one "Open anyway" in
the Chats view (untagged chat store), **no** prompt in the Users view (the
contact store is v4-tagged and gets its floor on the first persist). Log in
(Live room → step 1) and confirm the mailbox poller is not looping on 401
(`adb logcat | grep -i "401\|verify"` stays quiet after the first login).

Web client: same one-time Chats prompt in every browser profile that has
chat history.

## 3. On-device checks that only hardware can give

1. **Floor namespace through the real HMAC.** Re-run
   `android/native-floor-ondevice.mjs`, and additionally bump one id with each
   new prefix — `recv:<32hex>`, `exported:<32hex>`, `contacts:<64hex>`,
   `chats:<64hex>` — and read them back. The Node mock cannot show that the
   `:` survives `PadFloor.kt`'s `id\u0000value` MAC path; Kotlin sees a plain
   string, so it should, but "should" is not a proof.
2. **`FLAG_SECURE`.** Background the app, open recents: the card must be
   blank. `adb shell screencap -p /sdcard/x.png` while the app is in front:
   expect a failure or a black image.
3. **Dual login from the app.** After step 2 above, `/api/me` from the app
   must be 200 — the app's bundled `account.js` now sends `mldsa_sig`.
