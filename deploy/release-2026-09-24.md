# Release 0.3.0 (2026-09-24) — the contact profile

Thirteen commits on `claude/user-profile-view-e7qr9y`, merged into `master` as
PR #1 (`963b402`), plus this version bump. What changed, how it was checked,
how to deploy, and what to look at on a device.

## 1. What changed

Only the web client and the version string. No crypto, no wire format, no
relay behaviour, no DB change.

- Tap a saved user's row in Users, the avatar of a row in Chats, or the name
  in a conversation → a short profile as a sheet: handle, full fingerprint,
  trust mark and warnings, when saved / verified, and Message / Verified in
  person / Remove. Users rows got lighter (one button; the claim and
  key-changed lines stay in the list); Verify and Remove moved into the
  profile, next to the fingerprint they refer to.
- `client/app.js` (the sheet, its focus handling, `openContact` /
  `closeContact`, the simplified vouch retraction: vouch only for contacts
  added by handle, retract only on the user's own Unverify / Remove),
  `client/index.html` (`#contactSheet` and its scrim), `client/style.css`
  (`.contact-sheet`, `.scrim`, `.userlist`, `.chatrow`), `client/account.js`
  (`account.vouch` takes an optional abort signal), `client/contacts.js`
  (the stale-tab refusal is tagged `err.code = "STALE"`).
- `backend/config.py` `VERSION = "0.3.0"`; `android` `versionCode 3`,
  `versionName 0.3.0`. The APK bundles the client, so it needs a rebuild to
  show the profile, but the old APK keeps working against the new relay.

The brief, every review round and the known limits are in
`design/research/reviews/profile-brief.md` and `profile-fix-round-1..6.md`;
summary in `design/research/reviews.md`.

## 2. How it was checked

On the feature branch, per round: client unit tests, backend pytest (162),
the five existing e2e runs plus the new `e2e/contact-profile.mjs` (61 checks),
a design critic, an accessibility critic and a pentest of each diff until
clean. The trust core (Verify marks only the keys on screen) held from the
first pentest pass; the one Medium (pass 4: a stranger's claimed handle could
make us delete our real vouch) was fixed by removing that code, with a
mutation-proven regression check, and round 6 removed the rest of the
retraction bookkeeping. Known limit: the clean fix for the vouch cases is a
relay-side DELETE that names the exact vouch — not in this release.

The version bump itself (this commit) changes two strings and adds this file
and the deploy script; the client unit suite was re-run on it before the
merge.

## 3. Deploy

```bash
# on your machine, from the repo root
git checkout master && git pull
bash deploy/deploy-2026-09-24.sh        # backup, rsync, restart, verify (needs ssh to the box)
```

The script refuses to run on a checkout that is not 0.3.0. It verifies on the
box that `/healthz` reports `0.3.0`, that the served `index.html` carries the
tab bar and the contact sheet, `app.js` the admission guard and `openContact`,
`style.css` the tokens and the sheet, that the import map line is still there
(its CSP hash is unchanged), that the accounts count did not change, and that
`SECURE_CHAT_TRUSTED_PROXIES` is still unset.

Rollback, if ever: `git checkout v0.2.0 -- client backend/config.py` and run
the rsync + restart steps of this script; the DB is untouched by 0.3.0.

## 4. Android

```bash
git checkout master && git pull
(cd android && ANDROID_HOME=$HOME/Android/Sdk ./gradlew assembleDebug)   # the test phone is debug-signed; no keystore.properties exists
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

Then on the phone: unlock; open a contact from each of the three places
(Users row, Chats avatar, the name inside a conversation); the sheet must sit
above the tab bar and take focus, Close returns focus to where you came from;
verify one in person → the mark turns green; Remove asks first. Known: the
Android back button does not close the sheet (it navigates the view instead).
